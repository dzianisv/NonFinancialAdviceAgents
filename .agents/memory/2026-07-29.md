### <!-- retracted --> exemption marker shipped — 2026-07-29
Closes validator gap m12: the appendix correction table quotes each wrong figure **as originally drafted** so the error stays auditable, but the validator read those quotes as live claims and MISMATCHed them forever. Deleting them to go green would destroy the audit trail the tool protects.
**Design principle: an exemption marker is a SUPPRESSION mechanism — design against its own abuse.**
- Exempted claims are **never dropped** — they appear as `RETRACTED`, and the summary prints `⊘ N of M claim(s) EXEMPTED (… value-scoped, … whole-line)`. Invisible suppression is the failure mode.
- **Value-scoped by default:** `<!-- retracted: $0.410, $0.518 — prose -->` exempts ONLY those values; every other claim on the line stays verified. Whole-line (bare marker) is the documented BLUNT FALLBACK.
- **A listed value matching nothing = hard MARKER_ERROR.** A stale exemption that silently keeps suppressing after the text changed is the rot vector.
- Unclosed / nested `retracted:start`, stray `end` = hard errors (ambiguous scope, would exempt to EOF).
- >25% exempted trips a WARNING — a report mostly made of exemptions is a smell.
**Line-scope was tried first and was WRONG:** it suppressed **6** claims when only **4** were quoted retractions — the AERO appendix row carries the *corrected* range `$0.3018↔$1.4907` in the same table row, so marking the row silently **lost coverage on 2 correct values**. Value scope recovered them (both now `OK`). **Lesson: any suppression scope wider than the thing being suppressed will silently disable verification of correct data.**
**Self-widening bug worth remembering:** the first value-scoped attempt read values out of the marker's own explanatory prose (`the corrected $0.3018 ↔ $1.4907 …`), so the marker widened its own scope by explaining itself. Fixed by parsing values only from the HEAD before the first ` — `/`;`. En-dash then collided as both minus-sign and separator; resolved positionally.
Tests 94 → 109. Independently mutation-verified twice (marker errors not failing the run → 1 fail; value scope ignored → 7 fail).
Report now: 78 claims, all pass the basis gate, 4 exempted (4 value-scoped, 0 whole-line).
